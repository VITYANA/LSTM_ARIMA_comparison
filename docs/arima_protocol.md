# Протокол выбора ARIMA

Документ фиксирует процедуру выбора ARIMA до расчёта и интерпретации её
validation-результатов. Цель этапа — выбрать воспроизводимый порядок отдельно
для каждого основного тикера и сравнить выбранную модель с `naive_zero`, не
используя final test.

## Область этапа

Модель прогнозирует логарифмическую доходность следующего торгового дня.
Основной эксперимент использует `SPY`, `AAPL`, `JPM` и `XOM`. В этап входят
train-поиск кандидатов, ежедневный validation backtest и выбор порядка по
validation-метрикам. Прогнозирование final test, LSTM, гибрид ARIMA-LSTM и
стресс-тест `TSLA` выполняются на следующих этапах.

## Пространство кандидатов

Для каждого тикера на train проверяются 36 моделей:

```text
ARIMA(p, 0, q), где p ∈ {0, 1, 2, 3, 4, 5}, q ∈ {0, 1, 2, 3, 4, 5}
```

`d=0` зафиксирован по результатам ADF и KPSS для логарифмических доходностей.
Интерфейс поиска принимает настраиваемые `d_values`, но изменение `d` не входит
в основной эксперимент и должно рассматриваться как заранее объявленный
стресс-тест.

## Train-поиск и BIC shortlist

Каждый кандидат обучается только на строках своего тикера с `split == "train"`.
Для него сохраняются:

```text
ticker, p, d, q, aic, bic, converged, status
```

Кандидат допустим, если обучение завершилось без исключения, оптимизатор сообщил о сходимости, а AIC и BIC конечны. Неудачный кандидат остаётся в таблице поиска со статусом причины и не участвует в shortlist.

Допустимые модели сортируются по возрастанию исходного, неокруглённого BIC.
Для каждого тикера сохраняются три лучших порядка с рангами `1..3` и именами
`arima_bic_1`, `arima_bic_2`, `arima_bic_3`. Если допустимых моделей меньше
трёх, расчёт останавливается с ошибкой.

## Ежедневный validation backtest

Каждый кандидат проходит отдельный expanding-window backtest. Для прогноза на
`target_date` модель заново обучается на истории того же тикера, где:

```text
split != "test" и date <= текущей origin date
```

Таким образом, в историю входит уже наблюдаемая доходность на origin date и
предыдущая доступная часть validation, но не будущая целевая доходность и не
final test. Ошибка ежедневного обучения останавливает backtest; автоматическая
замена прогноза на `naive_zero` запрещена.

## Защита от утечки

`target_return` доступен только evaluation-слою для сопоставления прогноза с
фактом. Перед вызовом fitter и `ForecastModel.predict` столбец удаляется.
Final test не передаётся train-поиску, validation backtest, выбору порядка,
метрикам или промежуточной интерпретации.

## Окончательный выбор на validation

Три кандидата сравниваются отдельно для каждого тикера. Победитель определяется
по следующему детерминированному ключу на неокруглённых значениях:

1. минимальный validation MAE;
2. минимальный validation RMSE;
3. минимальная сложность `p + d + q`;
4. минимальный train BIC;
5. меньший `p`;
6. меньший `q`.

Прогнозы победивших порядков объединяются под общим именем `arima` и сравниваются
с `naive_zero` на идентичных validation-наблюдениях.

## Выходные таблицы

Этап формирует:

- полный train AIC/BIC ranking со статусами кандидатов;
- top-3 shortlist каждого тикера;
- validation-прогнозы трёх кандидатов;
- validation-метрики кандидатов с параметрами `p`, `d`, `q`, BIC и BIC rank;
- выбранный порядок каждого тикера;
- объединённые validation-прогнозы модели `arima`;
- ticker-level и pooled-сравнение `arima` с `naive_zero`.

## Ограничения интерпретации

Validation используется для выбора гиперпараметров, поэтому полученные на ней
метрики не являются независимой оценкой обобщающей способности. Они описывают
процедуру model selection. Итоговые выводы о качестве фиксированной модели
можно делать только после однократного открытия final test на отдельном этапе.

## Критерии завершения

- Для каждого основного тикера построен полный train ranking 36 кандидатов.
- Для каждого тикера сформирован top-3 из сошедшихся моделей с конечным BIC.
- Все три кандидата прошли ежедневный expanding-window validation backtest.
- Порядок каждого тикера выбран по зафиксированному ключу.
- Выбранная ARIMA сравнена с `naive_zero` на одинаковых validation-строках.
- Ни модель, ни fitter не получают `target_return` или строки final test.
- Final test не открыт и не отображён в результатах этапа.
