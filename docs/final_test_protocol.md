# Протокол независимой final-test оценки

Документ фиксирует итоговую процедуру до открытия результатов final test.
После запуска модели, правила обучения, метрики и статистические сравнения не
изменяются на основании test-результатов.

## Назначение и область

На периоде с 02.01.2020 по 31.12.2025 сравниваются четыре модели:
`naive_zero`, ARIMA, LSTM и ARIMA-LSTM. Основной эксперимент включает `AAPL`,
`JPM`, `SPY` и `XOM`. `TSLA` не входит в этот этап.

Разбиение определяется по `target_date`:

- train: 03.01.2006–31.12.2015;
- validation: 04.01.2016–31.12.2019;
- final test: 02.01.2020–31.12.2025.

Train и validation разрешены для финального обучения. Test используется один
раз для независимой оценки и не участвует в выборе конфигураций, эпох, seed,
метрик или статистических тестов.

## Зафиксированные модели

Порядки ARIMA и конфигурации LSTM выбраны на validation:

| Тикер | ARIMA | LSTM `(window, units, dropout)` | Residual LSTM `(window, units, dropout)` |
|---|---|---|---|
| AAPL | `(0, 0, 0)` | `(5, 32, 0.0)` | `(5, 32, 0.0)` |
| JPM | `(0, 0, 1)` | `(63, 16, 0.2)` | `(63, 32, 0.2)` |
| SPY | `(0, 0, 2)` | `(21, 32, 0.2)` | `(21, 32, 0.0)` |
| XOM | `(2, 0, 1)` | `(5, 16, 0.2)` | `(5, 32, 0.2)` |

Для каждой LSTM используются seed `0..9`. Ансамбль допустим только при десяти
успешных seed и равен арифметическому среднему их выровненных прогнозов.

## Финальное обучение LSTM

Обычная и residual LSTM обучаются отдельно для каждого тикера и seed:

1. последовательности `train + validation` делятся хронологически в отношении
   80/20;
2. последняя часть определяет эпоху минимального inner-validation loss;
3. сеть переинициализируется тем же seed;
4. сеть обучается на всех последовательностях `train + validation` ровно
   найденное число эпох.

На первом шаге scaler оценивается только по внутренней train-части, на втором —
только по `train + validation`. Используются Adam с learning rate `0.001`, MSE,
batch size `32`, максимум `200` эпох, early-stopping patience `15`,
`min_delta=0.0` и `shuffle=False`.

На test веса и scaler не обновляются. Поздние test-окна могут включать только
доходности или остатки, уже реализованные к соответствующей origin date.

## ARIMA и гибрид

ARIMA переобучается на каждой test origin date на expanding history. История
содержит train, validation и только уже наблюдавшиеся test-доходности. Порядок
модели остаётся фиксированным.

Для residual dataset первые `252` наблюдения каждого тикера образуют warm-up.
После него псевдовневыборочный остаток определяется как:

```text
residual[t] = actual_return[t] - arima_prediction[t]
```

Residual LSTM прогнозирует следующий остаток. Seed-level и ensemble-прогнозы
гибрида строятся только после точного выравнивания observation keys:

```text
arima_lstm_prediction = arima_prediction + residual_lstm_prediction
```

## Защита от утечки

- `target_return` удаляется до передачи истории и наблюдений модели;
- ARIMA-history заканчивается текущей origin date;
- test не участвует в выборе эпохи, обучении весов и оценке scaler;
- фактическое test-значение влияет только на прогнозы после его реализации;
- границы режимов волатильности оцениваются только на `train + validation`;
- четыре итоговые модели обязаны иметь одинаковые полные test-ключи;
- модельные функции не получают итоговые метрики или результаты статистики.

Нарушение любого ограничения останавливает pipeline. Пропуск неуспешной строки
или seed и автоматическая замена прогноза на `naive_zero` запрещены.

## Режимы волатильности

Для каждого тикера рассчитывается trailing standard deviation доходности за
21 торговый день с `ddof=1`, заканчивающаяся на origin date. Отображаемая
волатильность годизируется множителем `sqrt(252)`.

Терцили 1/3 и 2/3 оцениваются отдельно для каждого тикера по
`train + validation`. На test применяются фиксированные границы:

- `low`: волатильность не выше нижнего терциля;
- `medium`: выше нижнего и не выше верхнего терциля;
- `high`: выше верхнего терциля.

## Метрики

Для каждого тикера и общей pooled-таблицы рассчитываются MAE и RMSE доходности
в базисных пунктах, RelMAE, вневыборочный R² относительно `naive_zero` и
directional accuracy. Эти же метрики рассчитываются отдельно по трём режимам.
Pooled MAE и RMSE строятся по всем наблюдениям, а не усреднением ticker-level
метрик.

Однодневные цены восстанавливаются по формулам:

```text
predicted_price[t+1] = adjusted_price[t] * exp(predicted_return[t+1])
actual_price[t+1] = adjusted_price[t] * exp(actual_return[t+1])
```

Для каждого тикера рассчитываются price MAE, RMSE, sMAPE и MASE. Масштаб MASE —
среднее `abs(target_price - adjusted_price)` на `train + validation`; он должен
быть конечным и положительным. Pooled sMAPE и MASE — macro-average четырёх
ticker-level значений. Долларовые MAE и RMSE между тикерами не объединяются.

## Статистические сравнения

Заранее зафиксированы пять направленных пар `candidate - comparator`:

1. ARIMA против `naive_zero`;
2. LSTM против `naive_zero`;
3. ARIMA-LSTM против `naive_zero`;
4. ARIMA-LSTM против ARIMA;
5. ARIMA-LSTM против LSTM.

Отрицательная разница ошибки означает преимущество candidate. Тест
Диболда—Мариано выполняется для абсолютной и квадратичной ошибки отдельно по
каждому тикеру и pooled. Pooled loss differential сначала усредняется между
тикерами на общей target date. Используется двусторонний тест, Newey–West
long-run variance с Bartlett weights и лагом `20`.

Поправка Holm применяется к пяти p-value внутри каждой семьи
`scope × loss` при уровне `0.05`. Для разницы MAE и RMSE рассчитываются
95%-е percentile-интервалы moving-block bootstrap: блок `21` торговый день,
`10 000` повторений и seed `42`. В pooled bootstrap одинаковые блоки дат
применяются ко всем тикерам одновременно.

## Checkpoint и воспроизводимость

Локальные результаты сохраняются в игнорируемой директории
`artifacts/final_test/` как атомарные пары JSON/CSV. Отдельно сохраняются
expanding ARIMA-прогнозы, seed-level прогнозы обычной и residual LSTM и
итоговая выровненная таблица четырёх моделей. Pickle-файлы не используются.

Fingerprint включает SHA-256 исходного датасета, полный `FinalTestProtocol`,
параметры обучения и версии Python, NumPy, pandas, statsmodels,
scikit-learn и TensorFlow. При загрузке проверяются fingerprint, checksum,
схема, статус, ticker, seed и полное ожидаемое расписание ключей.

Совместимые завершённые части повторно не обучаются. Несовместимый, неполный
или повреждённый checkpoint отклоняется.

## Критерии завершения

- протокол и fingerprint совпадают с зафиксированными значениями;
- все ARIMA-прогнозы и оба набора по десять LSTM seed завершены;
- четыре модели выровнены на полном final-test расписании;
- рассчитаны return, price и regime metrics;
- выполнены пять сравнений DM и bootstrap;
- notebook завершён без ошибок, а выводы H1–H4 основаны на заранее
  определённых правилах;
- отрицательные и статистически незначимые результаты отражены без изменения
  протокола post hoc.
